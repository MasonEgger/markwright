- When CLAUDE.md names a process skill (`/bpe:brainstorm`, `/bpe:plan`, `/bpe:goal`) that the session's skill list lacks, stop and report it before implementing; hand-written spec/plan/todo files plus direct implementation are not a substitute, and Mason discarded a green, fully tested pass over exactly this (2026-10-15)
- When a `plan.md` is replaced or regenerated mid-cycle (a spec/plan swap for a remediation pass, a re-scope), regenerate `todo.md` in the same commit; `/bpe:goal` pre-flight only checks for zero unchecked items, so a `todo.md` left over from a prior, already-completed plan passes the "has unchecked items" check as fully done and silently blocks the loop (2026-09-07)
- When `/goal @goal.md` targets a file that does not exist, reconstruct the goal from the newest `.ai-sessions/` summaries (which name the intended next action) instead of guessing or asking blind; here the prior session's handoff said to execute `todo.md` Steps 1-6, so writing `goal.md` from that and proceeding was correct (2026-09-23)
- A `bpe:goal` remediation step whose plan.md cites an exact upstream source line (e.g. `compare.js:110`) needs that source fetched by the orchestrator and handed to the executor as a literal string in the dispatch prompt; the `step-executor` subagent has no web access to fetch it itself (2026-09-14)

## CLI
- Library code raises and only the CLI boundary turns exceptions into exit codes: helpers like `cli._resolve` should raise `ConfigError` instead of returning `None` for the caller to map to `2`, unknown flag values belong in argparse `choices`, and `main` holds the single `except (ConfigError, ConfigWarning)` that prints `mw: error:` and returns 2 (2026-10-11)
- One rule for every config list: omitted means default, a list names exactly what it holds (empty allowlist = none, empty denylist = nothing removed, never empty = everything), and a setting that makes a feature a no-op stays legal but emits `ConfigWarning` via `warnings.warn`, not `logging`: the Python Logging HOWTO reserves `warnings.warn` for avoidable issues the client should fix, it dedupes per location (MkDocs builds one `Markdown` per page, so a logged warning would print per page), and hosts can escalate it with `simplefilter("error", ConfigWarning)`; the CLI prints it via a `showwarning` swap inside `warnings.catch_warnings()` (2026-10-11)
- `registry.select_extensions` treats an empty `use` list as "all extensions", so feeding an already-resolved selection back into it re-selects everything when config disables every extension; apply CLI `--exclude` on top of `config.selected_extensions` by membership filtering (`select_extensions([], exclude)` only to validate the names) (2026-10-11)
- When a REFACTOR prompt says "factor stdin/stdout helpers" but the project bans trivial stdlib wrappers, factor only the non-trivial shared logic (e.g. a `_resolve_selection` that calls `select_extensions` and prints the `ValueError` to stderr, returning `None` to signal exit 2) and leave `sys.stdin.read()`/`sys.stdout.write()` inline (2026-06-28)
- Give an argparse-based `main(argv) -> int` a testable exit-code contract by wrapping `parser.parse_args` in `try/except SystemExit` and returning `exit_error.code`; this captures both the `action="version"` exit (0) and invalid-choice usage errors (2) without letting `SystemExit` escape to `capsys`-driven tests (2026-06-28)

## Testing
- `mw pre` expands `[grid]`, `[annotate]`, and the 0.1.0 embed directive lines inside fenced code blocks, while the in-process render does not (its preprocessors at priority 20 run after superfences stashes the fences); mermaid and icons already scan through `_fences`, the directive-line stages do not, and `tests/test_roundtrip.py`'s hypothesis grammar never places a directive inside a fence, so the parity test misses it; add that case to the grammar when fixing (2026-10-20)
- Python-Markdown serializes element attributes in sorted order, so a pre stage that emits the same element as an in-process `InlineProcessor` must write its attributes alphabetically (`aria-hidden` before `class`) or the roundtrip parity test fails on byte order (2026-10-15)
- When rewriting test helpers into fixtures with a split-by-`def test_` script, the fixture definition lands inside a neighboring piece and gets rewritten too (here into a self-recursive call), and an end marker like the next `class` can swallow an adjacent helper; scope such scripts to function bodies and diff the result before running tests (2026-10-11)
- Porting an upstream regex for parity means matching its exact tolerance, including what it rejects: the ported Instagram grammar (`INSTAGRAM_RE`) dropped a trailing-query tolerance markwright's own regex had added, because upstream's grammar ends right after the shortcode capture group; a test that pinned the old, more permissive behavior had to be replaced rather than kept alongside the new one (2026-09-14)
- A "make every consumer agree" fix is only proven by a test that drives every consumer (in-process render, `mw pre`, `mw pre | post`) from one shared input; a per-consumer test suite let a third divergence (an escaped prose marker surviving `mw pre` but not the `pre | post` pipeline) hide behind two passing single-consumer tests until the parity test forced all three through the same case (2026-09-14)
- A unit test suite cannot detect a runtime dependency declared only in a dev dependency group, because the dev group is already installed in the environment the unit suite runs in; only a clean-venv install probe from the built wheel (no dev group) reproduces the missing-import failure, so it belongs in the integration suite, not the unit gate (2026-09-08)
- An "A render equals B render" equivalence test can pass vacuously when both sides degrade identically; pair it with a presence-assertion test confirming each feature actually lands in the output. When only inter-block whitespace differs, normalize by collapsing blank lines outside `<pre>` (stash pre blocks first) to keep significant code-block whitespace intact (2026-06-28)
- A test can pass while the bug is live if it only asserts substrings that survive the corruption; write the RED assertion against the actual broken output (no `<code>`, no `<p><tag>`) (2026-06-27)
- When a coverage gap points at one line, trace it to the exact code path before writing the test — a same-looking input may exercise a different path (2026-06-26)
- Adding a parallel code path for an existing behavior needs its own test even when an analogous test exists for the old path (2026-06-26)

## Tooling
- Hatch's default `license-files` glob matches any `LICENSE`-named file under the project, so a `docs/icons/LICENSE` crediting third-party assets lands in the sdist and fails the sdist allowlist test; name such credits `CREDITS.txt` (2026-10-20)
- Switching the build backend from uv_build to hatchling silently changed the sdist from the package plus tests to every git-tracked file (session notes, CLAUDE.md, plans, docs, CI config); set `[tool.hatch.build.targets.sdist] include` explicitly and keep an integration test that asserts the sdist's top-level entries against an allowlist (2026-10-11)
- Before adding a new CPython to a project, update uv first (`uv self update`): uv 0.10.9 offered only `3.15.0a6`, where PyYAML's source build failed, while uv 0.13.0 installed the final 3.15.0 and everything passed; in CI, let uv supply the interpreter from `.python-version` instead of `actions/setup-python`, whose release list can lag a new CPython (2026-10-11)
- Ruff's TC fixer moves imports used only in annotations under `TYPE_CHECKING`, which breaks pydantic models (field annotations resolve at runtime) and decorators like `@pytest.fixture`; keep those imports at runtime with a per-line `# noqa: TC00x` naming pydantic as the reason, and re-check imports after any `--fix` pass (2026-10-11)
- Adding `pip-audit` to CI surfaced 22 known vulnerabilities in a lock nobody had upgraded; run it locally before wiring it in, upgrade the lock, and raise a runtime dependency's floor to the first release without the advisory (found by auditing pinned candidates with `pip-audit --no-deps --disable-pip -r`), here `pymdown-extensions>=11.0.1` (2026-10-11)
- `.coverage` is a tracked binary artifact in this repo that shows as modified after every test run; do not stage it (2026-06-26)
- For "no forbidden characters" audits, use a Python codepoint scan (`for c in line if c in '...'`), never a shell grep with a zsh `$'...'` Unicode pattern; the latter silently matched nothing and falsely passed an em-dash (2026-06-26)

## Git
- A breaking CLI change (removing the `--use` flag) is a minor bump under 0.x SemVer (0.1.0 -> 0.2.0), never a patch; a patch (0.1.1) is for backward-compatible fixes only, so any existing invocation the change breaks rules it out (2026-09-23)
- When renaming a project, check whether the old name is a substring of a name you must keep (`do-markdown` is inside the upstream `do-markdownit`); use a negative-lookahead replace `do-markdown(?!it)` so the attribution is not corrupted (2026-06-27)
- Commit the spec/plan/todo artifacts before `/bpe:goal`; it refuses on a dirty tree and on a non-gitignored `goal.md`, and a clean tree keeps the run's "git status empty" completion condition valid (2026-06-27)

## Security
- Escaping `<`/`>` to their JSON `\uXXXX` forms after `json.dumps` is a general technique for embedding data inside an HTML comment (`<!-- ... -->`): it removes every literal `<`/`>` from the payload so `-->`/`<!--` can never form inside it, and `json.loads` decodes `\uXXXX` transparently, so the read side needs no change (2026-09-08)

## Python
- A shared helper that takes a payload dict should annotate the parameter `Mapping[str, object]`, not `dict[str, object]`: `dict` is invariant in its value type, so a caller holding `dict[str, str]` (fence's marker payload) fails mypy, while `Mapping` is covariant in the value (2026-10-20)
- mypy strict rejects indexing a `TypedDict` with a runtime/variable key (`spec[stage_key]` raises `literal-required`); to iterate over fields generically, pass literal-key accessor callables (`lambda spec: spec["pre"]`) instead of string key names (2026-06-28)
- Make a shared math helper total rather than letting a degenerate input raise: `reduce_fraction`'s `math.gcd(0, 0) == 0` fed a floor division that raised `ZeroDivisionError` on any zero operand, and one caller (a youtube embed directive) could reach it with attacker- or author-controlled zero dimensions and abort a whole in-process MkDocs build; guard both the shared helper (return the operands unchanged on a zero operand, never raise) and the specific caller (normalize non-positive dimensions to a sane default before calling it), so the helper is safe for every future caller and the caller's fallback behavior stays caller-specific (2026-09-08)

## Python-Markdown
- The annotate postprocessor runs at a higher priority than the fence postprocessor so the fence marker is still a comment token when the annotated block is located; at fence's priority the marker is already consumed and the block cannot be found (2026-10-20)
- When replacing a whole comment span (a code-block annotation comment), keep the span's trailing newline, or the next code line merges into the previous one (2026-10-20)
- Python-Markdown's `normalize_whitespace` preprocessor (priority 30) strips the STX/ETX bytes around an `htmlStash` placeholder, so a preprocessor registered above 30 (anything that must run ahead of superfences) cannot stash; emit raw HTML inline and let the `html_block` preprocessor (priority 20) carry it, which is why the embeds at 20 can stash and a fence-replacing stage cannot (2026-10-15)
- Python-Markdown serializes element attributes in sorted order, so a pre stage that emits the same element as an in-process `InlineProcessor` must write its attributes alphabetically (`aria-hidden` before `class`) or the roundtrip parity test fails on byte order (2026-10-15)
- Python-Markdown's raw-HTML block scanner recognizes a block only within three spaces of indentation, so raw HTML inside a list item (an embed, a replaced fence) renders inside `<p>` in-process while Goldmark handles it; test indented raw blocks on the pre stage and through Hugo, not in-process (2026-10-15)
- To post-process rendered HTML without changing bytes you did not mean to touch, tokenize with the stdlib `html.parser` (`convert_charrefs=False`, offsets from `getpos()` against a `\n`-only line table, since `getpos` counts only `\n`) and apply span edits back to front; a tree parser such as lxml or selectolax re-serializes the whole page and breaks byte-identical output (2026-10-11)
- Python-Markdown's `Extension.setConfig` runs a `None` default through `parseBoolValue`, coercing a list to a bool, so an option that must tell "omitted" from "empty list" needs a sentinel default (`_ALL_ENVIRONMENTS = object()`) and must be read in `extendMarkdown`, not `__init__`: sniffing `**kwargs` in `__init__` silently ignores a later `setConfig` and leaves `getConfig` disagreeing with behavior (2026-10-11)
- Signature-based script injection must ignore embeds deferred inside `<template class="mw-embed-content">`: strip those regions before the `SIGNATURE in html` check (`has_eager_embed`), so a click-to-load page gets no provider script and a mixed page gets exactly one, and the decision still comes from the HTML alone, keeping `mw post` stateless (2026-10-11)
- Python-Markdown raises `KeyError` for any config key an `Extension` did not declare, so a new option needs `self.config = {...}` set in `__init__` before `super().__init__(**kwargs)`; validate the value in `extendMarkdown` and pass it into the preprocessor, so a bad value fails when `markdown.Markdown` is constructed, matching the `ValueError` the `expand_source` path raises (2026-10-11)
- To add a per-extension options channel to the pre stage, follow the existing `PostFn`/`warnings` convention: give every `expand_source` an `options: Mapping[str, object] | None = None` param it ignores (only `fence` reads `allowed_environments` from it), so `run_pre` threads `options.get(name)` to each stage uniformly with no per-extension branching in the registry (2026-09-23)
- Keep a registry-facing stage function at a fixed signature (`apply_html(html, warnings=None)`) and route the in-process processor through the same private core (`_apply_marker(..., label_class, secondary_label_class)`) so configurable in-process options survive without giving the pure function config parameters (2026-06-28)
- Script-embed postprocessors can detect their class signature in the rendered HTML instead of carrying a preprocessor `found` flag: raw-HTML restore (priority 30) runs before script injection (priority 15), so the stashed embed HTML is already present; `SIGNATURE in html and SCRIPT not in html` makes the inject idempotent and shares one code path with the CLI post stage (2026-06-28)
- Extensions that emit raw HTML from a preprocessor must stash it via `self.md.htmlStash.store(html)`; otherwise Markdown keeps parsing the output (JS backticks become `<code>`, block elements get an invalid `<p>` wrap) (2026-06-27)
- Diagnose render bugs by converting the failing case through the real extension stack and reading the HTML; that separates markdown-output bugs from theme CSS (2026-06-27)
